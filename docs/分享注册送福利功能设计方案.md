# 🎁 分享注册送福利功能设计方案

> **版本**: v1.0  
> **适用项目**: Pixelle-Video (ZuoSuo AI 视频创作平台)  
> **目标**: 通过老用户分享邀请 + 新用户注册奖励的裂变机制，驱动用户增长

---

## 一、需求概述

通过"老用户分享邀请链接，新用户注册即送福利"的裂变传播机制，吸引用户主动帮助平台传播。

**核心流程**：
1. 已注册用户生成**专属邀请链接/二维码**
2. 新用户通过链接注册（填写邀请码）
3. 新用户**完成至少1次视频生成**后
4. **邀请人**获得奖励 + **被邀请人**获得新人福利

---

## 二、核心机制设计

### 2.1 邀请码体系

每个用户注册后**自动生成**唯一的6位字母+数字邀请码。

| 属性 | 说明 |
|------|------|
| **格式** | 6位字母+数字组合，如 `A3K8XQ` |
| **生成算法** | 基于用户ID + 随机盐值 → base36编码 → 截取前6位 → 冲突时自增重试 |
| **邀请链接** | `https://xxx.com/register?invite_code=A3K8XQ` |
| **二维码** | 自动生成的二维码图片（含邀请链接） |

### 2.2 奖励规则

| 奖励项 | 触发条件 | 邀请人奖励 | 被邀请人奖励 | 说明 |
|-------|---------|-----------|-------------|------|
| 🥇 **基础奖励** | 被邀请人完成**1次**视频生成 | +3 次生成次数 | +2 次生成次数 | 核心激励 |
| 🥈 **进阶奖励** | 被邀请人完成**3次**视频生成 | +1 天 VIP 体验 | +1 天 VIP 体验 | 促留存 |
| 🏆 **高阶奖励** | 累计邀请**5人**有效 | +7 天 VIP 体验 | — | 激励核心传播者 |

**次数说明**：
- "生成次数"为**一次性额外次数**，不占用每日限额，用完即止
- 存储在 `user_bonus.bonus_generations` 字段中
- 使用顺序：**每日限额用完 → 消耗 bonus_generations**

**VIP体验说明**：
- 普通用户：直接升级为VIP，体验到期后回退为普通用户
- 已有VIP用户：延长VIP有效期
- 已有SVIP用户：不叠加（SVIP已无限制）

### 2.3 防作弊策略

| 策略 | 规则 |
|------|------|
| **IP 限制** | 同一IP 24小时内仅第1次注册计为有效邀请 |
| **设备指纹限制** | 前端采集 Canvas + WebGL 指纹，同一设备仅计1次 |
| **行为门槛** | 被邀请人必须**完成至少1次视频生成**，邀请人才能获得奖励 |
| **风控阈值** | 单日邀请超过20人触发人工审核标记 |
| **连带惩罚** | 若被邀请人因违规被封禁，对应的邀请奖励自动撤回 |

## 三、数据库设计

### 3.1 现有表修改：`users`

```sql
-- 新增字段
ALTER TABLE `users`
ADD COLUMN `invite_code` VARCHAR(10) DEFAULT NULL UNIQUE COMMENT '我的邀请码' AFTER `phone`,
ADD COLUMN `invited_by` INT DEFAULT NULL COMMENT '邀请人用户ID' AFTER `invite_code`;

-- 新增索引
ALTER TABLE `users` ADD INDEX `idx_invited_by` (`invited_by`);
```

### 3.2 新增表：`invite_codes`（邀请码表）

```sql
CREATE TABLE IF NOT EXISTS `invite_codes` (
    `id` INT AUTO_INCREMENT PRIMARY KEY,
    `user_id` INT NOT NULL COMMENT '用户ID',
    `invite_code` VARCHAR(10) NOT NULL UNIQUE COMMENT '唯一邀请码(6位字母数字)',
    `total_invites` INT NOT NULL DEFAULT 0 COMMENT '累计有效邀请数',
    `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY `uk_invite_code` (`invite_code`),
    INDEX `idx_user_id` (`user_id`),
    FOREIGN KEY (`user_id`) REFERENCES `users`(`id`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

### 3.3 新增表：`invite_records`（邀请记录表）

```sql
CREATE TABLE IF NOT EXISTS `invite_records` (
    `id` INT AUTO_INCREMENT PRIMARY KEY,
    `inviter_id` INT NOT NULL COMMENT '邀请人用户ID',
    `invitee_id` INT NOT NULL COMMENT '被邀请人用户ID',
    `invite_code` VARCHAR(10) NOT NULL COMMENT '使用的邀请码',
    `status` ENUM('pending','completed','advanced','rewarded') NOT NULL DEFAULT 'pending'
        COMMENT 'pending=已注册未完成;completed=已完成1次;advanced=已完成3次;rewarded=已发放奖励',
    `invitee_ip` VARCHAR(45) DEFAULT NULL COMMENT '被邀请人注册IP',
    `invitee_device_fp` VARCHAR(64) DEFAULT NULL COMMENT '被邀请人设备指纹',
    `base_reward_granted` TINYINT NOT NULL DEFAULT 0 COMMENT '基础奖励(生成次数)是否已发放',
    `advanced_reward_granted` TINYINT NOT NULL DEFAULT 0 COMMENT '进阶奖励(VIP天数)是否已发放',
    `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `completed_at` DATETIME DEFAULT NULL COMMENT '首次完成视频的时间',
    `advanced_at` DATETIME DEFAULT NULL COMMENT '完成3次视频的时间',
    `rewarded_at` DATETIME DEFAULT NULL COMMENT '所有奖励发放完成时间',
    INDEX `idx_inviter_id` (`inviter_id`),
    INDEX `idx_invitee_id` (`invitee_id`),
    INDEX `idx_status` (`status`),
    UNIQUE KEY `uk_invitee` (`invitee_id`),
    FOREIGN KEY (`inviter_id`) REFERENCES `users`(`id`) ON DELETE CASCADE,
    FOREIGN KEY (`invitee_id`) REFERENCES `users`(`id`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

### 3.4 新增表：`user_bonus`（用户奖励余额表）

```sql
CREATE TABLE IF NOT EXISTS `user_bonus` (
    `id` INT AUTO_INCREMENT PRIMARY KEY,
    `user_id` INT NOT NULL UNIQUE COMMENT '用户ID',
    `bonus_generations` INT NOT NULL DEFAULT 0 COMMENT '额外生成次数余额',
    `total_earned_generations` INT NOT NULL DEFAULT 0 COMMENT '累计获得生成次数',
    `total_used_generations` INT NOT NULL DEFAULT 0 COMMENT '累计消耗生成次数',
    `total_invited_count` INT NOT NULL DEFAULT 0 COMMENT '累计有效邀请人数',
    `vip_bonus_days` INT NOT NULL DEFAULT 0 COMMENT '累计获得VIP体验天数(未兑换)',
    `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (`user_id`) REFERENCES `users`(`id`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

### 4.4 关键业务数据流

#### 流程1：新用户注册（带邀请码）

```
POST /api/auth/register (body: {username, password, invite_code: "A3K8XQ"})
  │
  ├─ 1. 校验基本注册信息
  ├─ 2. 检查 invite_code 有效性（调用 invite/service）
  │     ├─ invite_codes 表查找是否存在
  │     └─ 检查邀请人账号状态是否正常
  ├─ 3. 风控检查（IP、设备指纹）
  ├─ 4. 创建用户
  │     ├─ users 表写入（invited_by = 邀请人ID）
  │     └─ 为新用户生成自己的邀请码
  ├─ 5. 创建邀请记录
  │     └─ invite_records 表写入（status = 'pending'）
  └─ 6. 返回 Token + 用户信息
```

#### 流程2：完成任务触发奖励（修改 `increment_daily_usage`）

```
用户完成视频生成 → increment_daily_usage(user_id)
  │
  ├─ 1. 原有逻辑：每日使用次数 +1
  │
  └─ 2. 新增：检查该用户是否是被邀请人
        ├─ invite_records 查找 invitee_id = user_id
        ├─ 如果 status = 'pending':
        │     ├─ 更新 status = 'completed', completed_at = now
        │     ├─ 发放基础奖励
        │     │     ├─ 邀请人(user_bonus)：bonus_generations += 3
        │     │     └─ 被邀请人(user_bonus)：bonus_generations += 2
        │     └─ 更新 invite_codes：total_invites += 1
        │
        └─ 如果 status = 'completed' 且已完成3次（检查 daily_usage）：
              ├─ 更新 status = 'advanced', advanced_at = now
              ├─ 发放进阶奖励
              │     ├─ 邀请人(user_bonus)：vip_bonus_days += 1
              │     └─ 被邀请人(user_bonus)：vip_bonus_days += 1
              │
              └─ 检查邀请人累计邀请数
                    └─ 如果 total_invites % 5 == 0：
                          ├─ 发放高阶奖励（vip_bonus_days += 7）
                          └─ 记录奖励发放日志
```

#### 流程3：消耗 bonus 次数（修改 `check_daily_limit`）

```
用户发起视频生成 → check_daily_limit(user)
  │
  ├─ 1. 原逻辑：检查 daily_usage 是否达上限
  │
  ├─ 2. 如果达上限：
  │     ├─ 检查 user_bonus.bonus_generations > 0
  │     ├─ 如果是：允许继续，准备消耗 bonus
  │     └─ 如果否：拒绝（"今日次数已用完"）
  │
  └─ 3. 任务执行完毕后：
        └─ 如果消耗了 bonus_generations
              ├─ user_bonus.bonus_generations -= 1
              └─ user_bonus.total_used_generations += 1
```

## 七、安全与风控

### 7.1 防刷机制

1. **IP 频率限制**：使用内存缓存或 Redis，对同一IP注册请求限流（每小时最多5次注册）
2. **邀请码暴力枚举防护**：`/api/invite/check/{code}` 接口限流（每分钟最多10次）
3. **注册邀请码校验**：邀请码必须存在于 `invite_codes` 表且对应用户状态正常

### 7.2 数据一致性

- 奖励发放使用**数据库事务**，确保 `invite_records` 状态更新和 `user_bonus` 更新原子性
- 若任务生成失败（回滚），需同步调用 `decrement_daily_usage` 类似逻辑回滚奖励触发状态
- 发放记录需记录操作日志，便于对账和问题排查

### 7.3 监控与运营

- 在管理后台增加"邀请数据统计"看板
  - 每日邀请注册数、有效转化率
  - 奖励发放总量（生成次数、VIP天数）
  - 作弊异常告警（同IP多账号、批量注册等）
- 邀请码支持管理员后台手动生成/作废

- 奖励发放逻辑要考虑**幂等性**（`base_reward_granted` 字段防止重复发放）
- 注册页的邀请码为**非必填**，不填不影响正常注册流程
- 前端二维码生成推荐使用 `qrcode` npm 包（纯前端渲染，无后端开销）

## 九、扩展性预留

- **多级邀请**：邀请记录表设计已预留多级扩展，可增加 `level` 字段实现二级邀请奖励
- **活动配置化**：奖励规则可抽离为配置表/配置文件，后续支持运营后台动态调整
- **积分体系**：`user_bonus` 表可扩展为通用积分账户，支持多种积分来源和消费场景
- **社交分享SDK**：对接微信/QQ等社交平台的JS-SDK，实现一键分享到朋友圈/好友
